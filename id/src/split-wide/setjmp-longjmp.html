34 Long Jump dengan setjmp, longjmp

Kita sudah melihat goto, yang melompat dalam function scope. Tapi longjmp() memungkinkanmu melompat kembali ke titik eksekusi yang lebih awal, kembali ke fungsi yang memanggil fungsi ini.

Ada banyak batasan dan peringatan, tapi ini bisa menjadi fungsi yang berguna untuk keluar dari kedalaman call stack kembali ke keadaan yang lebih awal.

Menurut pengalamanku, fungsionalitas ini sangat jarang dipakai.

34.1 Memakai setjmp dan longjmp

Tarian yang akan kita lakukan di sini pada dasarnya adalah menaruh penanda buku dalam eksekusi dengan setjmp(). Nanti, kita memanggil longjmp() dan ia akan melompat kembali ke titik eksekusi sebelumnya tempat kita menaruh penanda itu dengan setjmp().

Dan ini bisa dilakukan bahkan kalau kamu sudah memanggil subfungsi.

Berikut demo singkat ketika kita memanggil fungsi beberapa tingkat ke dalam lalu keluar darurat.

Kita akan memakai variabel file scope env untuk menyimpan state saat kita memanggil setjmp() sehingga bisa memulihkannya ketika memanggil longjmp() nanti. Inilah variabel tempat kita mengingat “posisi” kita.

Variabel env bertipe jmp_buf, tipe opaque yang dideklarasikan di <setjmp.h>.

#include <stdio.h>
#include <setjmp.h>

jmp_buf env;

void depth2(void)
{
    printf("Entering depth 2\n");
    longjmp(env, 3490);           // Keluar darurat
    printf("Leaving depth 2\n");  // Ini tidak akan terjadi
}

void depth1(void)
{
    printf("Entering depth 1\n");
    depth2();
    printf("Leaving depth 1\n");  // Ini tidak akan terjadi
}

int main(void)
{
    switch (setjmp(env)) {
      case 0:
          printf("Calling into functions, setjmp() returned 0\n");
          depth1();
          printf("Returned from functions\n");  // Ini tidak akan terjadi
          break;

      case 3490:
          printf("Bailed back to main, setjmp() returned 3490\n");
          break;
    }
}

Saat dijalankan, ini mengeluarkan:

Calling into functions, setjmp() returned 0
Entering depth 1
Entering depth 2
Bailed back to main, setjmp() returned 3490

Kalau kamu mencoba mencocokkan output itu dengan kodenya, jelas ada hal yang benar-benar aneh sedang terjadi.

Salah satu yang paling mencolok: setjmp() mengembalikan nilai dua kali. Apa-apaan ini? Sihir apa ini?!

Begini ceritanya: kalau setjmp() mengembalikan 0, artinya kamu berhasil menaruh “penanda buku” di titik itu.

Kalau ia mengembalikan nilai bukan nol, artinya kamu baru saja kembali ke “penanda buku” yang ditaruh sebelumnya. (Dan nilai yang dikembalikan adalah nilai yang kamu oper ke longjmp().)

Dengan cara ini kamu bisa membedakan antara menaruh penanda dan kembali ke penanda itu nanti.

Jadi ketika kode di atas memanggil setjmp() untuk pertama kali, setjmp() menyimpan state di variabel env dan mengembalikan 0. Nanti saat kita memanggil longjmp() dengan env yang sama, ia memulihkan state itu dan setjmp() mengembalikan nilai yang dioper ke longjmp().

34.2 Jebakan

Di balik layar, ini cukup lugas. Biasanya stack pointer melacak lokasi di memori tempat variabel lokal disimpan, dan program counter melacak alamat instruksi yang sedang dieksekusi180.

Jadi kalau kita ingin melompat kembali ke fungsi yang lebih awal, pada dasarnya tinggal memulihkan stack pointer dan program counter ke nilai yang disimpan di variabel jmp_buf, dan memastikan nilai kembaliannya diatur dengan benar. Lalu eksekusi akan dilanjutkan di sana.

Tapi berbagai faktor mengacaukan ini, menciptakan banyak jebakan undefined behavior.

34.2.1 Nilai Variabel Lokal

Kalau kamu ingin nilai variabel lokal otomatis (bukan static dan bukan extern) tetap bertahan di fungsi yang memanggil setjmp() setelah longjmp() terjadi, kamu harus mendeklarasikan variabel itu sebagai volatile.

Secara teknis, mereka hanya perlu volatile kalau nilainya berubah antara saat setjmp() dipanggil dan longjmp() dipanggil181.

Misalnya, kalau kita menjalankan kode ini:

int x = 20;

if (setjmp(env) == 0) {
    x = 30;
}

dan nanti longjmp() kembali, nilai x akan tak tentu.

Kalau ingin memperbaikinya, x harus volatile:

volatile int x = 20;

if (setjmp(env) == 0) {
    x = 30;
}

Sekarang nilainya akan benar, yaitu 30, setelah longjmp() membawa kita kembali ke titik ini.

34.2.2 Berapa Banyak State yang Disimpan?

Saat kamu longjmp(), eksekusi dilanjutkan di titik setjmp() yang bersesuaian. Dan hanya itu.

Spesifikasi menunjukkan bahwa itu sama saja seolah-olah kamu melompat kembali ke fungsi pada titik itu dengan variabel lokal bernilai apa pun yang mereka miliki saat pemanggilan longjmp() dilakukan.

Hal-hal yang tidak dipulihkan, memparafrasekan spesifikasi, mencakup:

  • Flag status floating point
  • File yang terbuka
  • Komponen lain apa pun dari abstract machine

34.2.3 Kamu Tidak Boleh Menamai Apa Pun setjmp

Kamu tidak boleh punya identifier extern bernama setjmp. Atau, kalau setjmp adalah makro, kamu tidak boleh meng-undefine-nya.

Keduanya undefined behavior.

34.2.4 setjmp() Tidak Boleh Berada dalam Ekspresi yang Lebih Besar

Artinya, kamu tidak bisa melakukan sesuatu seperti ini:

if (x == 12 && setjmp(env) == 0) { ... }

Itu terlalu kompleks untuk diizinkan spesifikasi karena rekayasa yang harus terjadi saat membongkar stack dan sebagainya. Kita tidak bisa longjmp() kembali ke ekspresi kompleks yang baru dieksekusi sebagian.

Jadi ada batas kompleksitas pada ekspresi itu.

  • Ia boleh menjadi seluruh ekspresi pengendali dari kondisional.

    if (setjmp(env)) {...}
    switch (setjmp(env)) {...}

  • Ia boleh menjadi bagian dari ekspresi relasional atau kesamaan, selama operand lainnya adalah konstanta integer. Dan keseluruhannya adalah ekspresi pengendali dari kondisional.

    if (setjmp(env) == 0) {...}

  • Operand dari operasi logical NOT (!), yang menjadi seluruh ekspresi pengendali.

    if (!setjmp(env)) {...}

  • Ekspresi mandiri, mungkin di-cast ke void.

    setjmp(env);
    (void)setjmp(env);

34.2.5 Kapan longjmp() Tidak Boleh Dilakukan?

Ini undefined behavior kalau:

  • Kamu belum memanggil setjmp() sebelumnya
  • Kamu memanggil setjmp() dari thread lain
  • Kamu memanggil setjmp() di scope sebuah variable length array (VLA), dan eksekusi sudah meninggalkan scope VLA itu sebelum longjmp() dipanggil.
  • Fungsi yang berisi setjmp() sudah keluar sebelum longjmp() dipanggil.

Untuk yang terakhir, “keluar” mencakup return normal dari fungsi itu, serta kasus ketika longjmp() lain sudah melompat kembali ke titik yang “lebih awal” di call stack daripada fungsi yang dimaksud.

34.2.6 Kamu Tidak Boleh Mengoper 0 ke longjmp()

Kalau kamu mencoba mengoper nilai 0 ke longjmp(), nilai itu akan diam-diam diubah menjadi 1.

Karena setjmp() pada akhirnya mengembalikan nilai ini, dan setjmp() yang mengembalikan 0 punya makna khusus, mengembalikan 0 dilarang.

34.2.7 longjmp() dan Variable Length Array

Kalau kamu berada di scope sebuah VLA dan longjmp() keluar dari sana, memori yang dialokasikan untuk VLA itu bisa bocor182.

Hal yang sama terjadi kalau kamu longjmp() melewati fungsi-fungsi sebelumnya yang masih punya VLA dalam scope.

Ini salah satu hal yang benar-benar mengganggu aku soal VLA—kamu bisa menulis kode C yang sepenuhnya sah tapi menyia-nyiakan memori. Tapi ya, aku bukan pemegang spesifikasi.
